# ポスト作成機能 設計

Issue: 未作成（作ったら番号をここに書く）

## 概要

今のアプリには、ポストを新しく書く画面がない（ポストはシーダーで入れたものだけ）。ログインした人が、タイムラインから入れる専用の画面でポストを書けるようにする。

- 専用ページ `/posts/create` を追加し、タイムラインのヘッダーに入口の「ポストする」リンクを1つ足す
- 項目は、今の編集画面と同じ「タイトル・トピック・本文」の3つ
- 書けるのはログインしている人だけ。投稿者は書いた本人で、ほかの人の名前で出せる形にはしない
- 送ったあとはタイムラインに戻り、新しいポストが先頭に出る
- 本文は必須で140字まで。上限は `Post::CONTENT_MAX_LENGTH` を使う

### 置き場所の決め方

置き場所は3案を比べて、専用ページにした。

| 案 | 場所 | タイムラインへの影響 |
| :- | :--- | :------------------- |
| A | タイムライン上部にフォーム | 大きい（`index.blade.php` と `index()` が変わる） |
| **B** | **専用ページ `/posts/create`** | **最小（リンク1つ）。`edit.blade.php` のフォームを流用できる** |
| C | `<dialog>` のモーダル | 中〜大（`index` に JS が増え、エラー時の開き直しが要る） |

「タイムラインの一覧・編集・削除を変えない」を守りやすいことと、既存の編集画面と作りが揃うことから B にした。

## 受け入れ条件

- [ ] ログインした状態でタイムラインを開くと、ポストを書く場所か、書く画面への入口がある
- [ ] タイトル・トピック・本文を入れて送ると、タイムラインの先頭にそのポストが増える
- [ ] 本文が空のまま送ると、エラーが表示されてポストは増えない
- [ ] 増えたポストには自分の名前が出ていて、編集と削除の操作が出る
- [ ] ログアウトすると、ポストを書く場所にたどり着けない（ログイン画面に飛ばされる）

## 決めごと

| 決めごと | 中身 |
| :------- | :--- |
| ポストが持つ項目 | 今の編集画面と同じ、タイトル・トピック・本文の3つ |
| 書ける人 | ログインしている人だけ |
| 投稿者 | 書いた本人。ほかの人の名前で出せる形にはしない（`user_id` はリクエストから受け取らず、ログイン中の人から入れる） |

## 変えないもの

| 変えないもの | 確かめ方 |
| :----------- | :------- |
| `posts` テーブルの列 | 列を足したり型を変えたりしない。`database/migrations` にファイルが増えていないことで確かめる |
| タイムラインの一覧・編集・削除 | 今の動きのまま。他人のポストには編集・削除の操作が出ず、URL を直接開くと 403 になる |
| ここまでに足したもの | リプライ機能と、編集画面の文字数制限・残り文字数の表示は、そのまま動く |

- `PostPolicy` と `ReplyController` は変えない
- タイムラインの見た目で変わるのは、ヘッダーに「ポストする」リンクを1つ足すところだけ

## 増えるテーブル

なし。`posts` テーブルをそのまま使う。

| 列 | 入れる値 |
| :- | :------- |
| user_id | ログイン中の人（リクエストでは受け取らない） |
| category_id | フォームで選んだトピック |
| title | フォームのタイトル |
| content | フォームの本文（140字まで） |

## 増える画面

| 画面 | 場所 | 見える人 | 内容 |
| :--- | :--- | :------- | :--- |
| ポストを書く画面 | `GET /posts/create` | ログインした人 | タイトル、トピック（選択）、本文（残り字数つき）、「投稿」「キャンセル」 |

あわせて、次の操作が増える。

| 操作 | 場所 | 画面での置き場所 | 終わったあと |
| :--- | :--- | :--------------- | :----------- |
| 書く画面へ行く | `GET /posts/create` | タイムラインのヘッダーの「ポストする」リンク | - |
| ポストを送る | `POST /posts` | 書く画面のフォーム | タイムラインに戻る（新しいポストが先頭） |

- 2つのルートは、認証が必要なグループ（`auth` ミドルウェア）の中に置く。`/posts/{post}` より前に書く（`create` が `{post}` に取られないようにするため）
- 「キャンセル」はタイムラインに戻るだけで、何も保存しない

### 並び順

タイムラインは新しい順（`latest()`）。同じ秒に作ったポストでも先頭が決まるよう、`latest('id')` を足す（詳細画面のリプライと同じ書き方）。

## 入力チェックとメッセージ一覧

### 入力チェック表（ポストを書く画面）

ポストの更新（`PostController::update`）と同じルールを使う。

| 画面 | 項目 | 必須 | 文字数・桁数 | 形式・値の範囲 | ほかの項目との関係 |
| :--- | :--- | :--- | :----------- | :------------- | :----------------- |
| ポストを書く画面 | タイトル | 必須 | 255字以内 | 文字列 | - |
| ポストを書く画面 | トピック | 必須 | - | `categories` に存在する id | - |
| ポストを書く画面 | 本文 | 必須 | 140字以内 | 文字列 | - |

- 改行は、ブラウザが CRLF で送るので、LF にそろえて1文字として数える（ポストの更新、リプライと同じ）
- 更新と送信で同じルール・同じメッセージを使うため、`PostController` の private メソッド `validatePost` にまとめた。リプライ（`ReplyController::store`）は本文だけなので、別のまま

### メッセージ一覧

| 場面 | 項目 | 条件 | メッセージ | 表示場所 |
| :--- | :--- | :--- | :--------- | :------- |
| ポストを送る | 本文 | 空 | 本文を入力してください。 | 本文欄の下（赤字） |
| ポストを送る | 本文 | 140字を超えている | 本文は140字以内で入力してください。 | 本文欄の下（赤字） |
| ポストを送る | タイトル、トピック | 条件に合わない | Laravel の標準メッセージ | 各欄の下（赤字） |
| どの操作も | - | ログインしていない | （ログイン画面へ移動する） | - |

- 入力チェックに引っかかったら、ポストは増やさず、入力した内容を欄に残す（`old()`）
- 送信先 `POST /posts` でエラーになったときは、書く画面に戻る

## テスト観点

Feature テストで確認する。`tests/Feature/PostCreateTest.php` に置き、`ReplyTest` と同じ書き方に揃える。

### 入口と画面

- タイムラインに、書く画面へのリンクが出る
- 書く画面に、トピックの選択肢が出る

### 送る

- 送るとタイムラインに戻り、`posts` に1件増える。タイムラインでは先頭に出る（既存のポストがあっても）
- 本文が空だとエラーが出て、ポストは増えない
- 本文が141字だとエラーが出て、ポストは増えない
- 改行を含む本文は、CRLF を LF にそろえて数える（改行を含めて140字ちょうどなら送れる）
- 増えたポストに自分の名前と、編集・削除の操作が出る
- リクエストで `user_id` を送っても、ログイン中の人のポストになる

### ログインしていない

- 書く画面が開けず、ログイン画面へ移動する
- 送れず、ポストは増えない

### 変わっていない

- 他人のポストは、編集画面を開くと 403、削除も 403 になり、タイムラインに編集・削除の操作が出ない
- リプライの全テストと、編集画面の入力チェック・残り字数のテスト（`ReplyTest`、`PostContentLimitTest`）が通る
- `database/migrations` にファイルが増えていない

## 確認の手順（手動）

1. `./vendor/bin/sail up -d` で起動し、`usera@example.com`（パスワード `password`）でログインする
2. 「ポストする」を押し、3項目を入れて送る → タイムラインの先頭に増え、自分の名前と編集・削除が出る
3. 本文を空にして送る → エラーが出て、増えない
4. ログアウトして `/posts/create` を直接開く → ログイン画面に移る
